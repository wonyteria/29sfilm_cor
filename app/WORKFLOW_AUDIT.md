# 29 WITH 기능 연결성 점검

## 이번 개선에서 연결한 흐름

1. 로그인 계정별 데이터 분리
   - 관리자는 전체 운영 데이터를 조회합니다.
   - 선생님은 본인의 프로필, 신청, 작품, 지급 쿠폰만 조회합니다.
   - 비로그인 상태에서는 운영 데이터 API를 조회할 수 없습니다.

2. 행사 운영 단계
   - 모집중 → 선정중 → 출품 확인 → 최종 확인 → 확인서 발급 → 심사 반영 → 종료 준비 → 종료 순서로 진행합니다.
   - 단계를 건너뛸 수 없습니다.
   - 선정 학교가 없으면 출품 확인을 시작할 수 없습니다.
   - 출품 엑셀이 없으면 최종 확인으로 넘어갈 수 없습니다.
   - 미매칭 작품이 있으면 확인서 발급으로 넘어갈 수 없습니다.

3. 신청과 선정
   - 같은 선생님은 같은 행사에 중복 신청할 수 없습니다.
   - 기존 학교명 또는 출품 소속명과 다른 값으로 재신청할 수 없습니다.
   - 우선 대상 → 일반 → 후순위 순으로 정렬하고, 같은 기준에서는 신청 시간이 빠른 순서로 표시합니다.
   - 선정 시 출품 슬롯을 만들고 미사용 쿠폰이 있으면 자동 배정합니다.

4. 출품 엑셀
   - 현재 선택한 행사 안에서만 분석합니다.
   - 선정된 학교의 학교명 또는 신청 당시 출품 소속명/팀명과 비교합니다.
   - 완전 일치, 띄어쓰기 또는 한 글자 차이, 미매칭으로 구분합니다.
   - 유사·미매칭 작품은 관리자가 학교를 선택해 확정할 수 있습니다.
   - 같은 행사 파일을 다시 올리면 이전 분석을 교체해 중복을 방지합니다.

5. 쿠폰
   - 쿠폰 번호를 인식하지 못하거나 모두 중복이면 오류 원인을 표시합니다.
   - 선정 시 자동 지급하고, 관리자와 선생님 화면에 지급 대상을 연결해 표시합니다.

6. 활동확인서
   - 행사별 모든 선정 학교를 각각 표시합니다.
   - 최종 매칭된 작품이 있고 행사 단계가 확인서 발급 이후일 때만 다운로드할 수 있습니다.
   - 서버가 로그인 사용자와 신청 소유자를 다시 확인하므로 다른 학교 문서를 받을 수 없습니다.

7. 메일
   - 초안 저장, 예약 저장, 즉시 발송을 분리합니다.
   - 저장한 메일을 다시 불러올 수 있습니다.
   - 현재 선택한 행사의 선정 학교만 수신 후보로 표시합니다.

## 다음 개발 우선순위

1. 학교명·출품 소속명 변경 요청과 관리자 이중 확인
2. 교사 증빙 파일 업로드와 관리자 확인
3. 간식비 금액·지급 예정일·지급 상태 관리
4. 활동확인서 승인 상태 저장과 수정 요청·답변
5. 심사표 PDF 저장, 공개 승인, 선생님 알림
6. D-14·D-10·D-5·D-1 메일 자동 생성과 관리자 승인함
7. 학교별 관리자 메모와 참여 이력 자동 집계
8. 행사 정보 수정, 비활성화, 종료 전 최종 점검표
9. 메일 템플릿과 발신자 설정 관리
10. 모든 변경 전후 값을 포함한 상세 감사 로그
